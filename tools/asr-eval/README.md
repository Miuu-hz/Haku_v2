# ชุดวัดการถอดเสียงไทย (P0.4 ชิ้น ง)

วัดว่า Gemma 4 ถอดเสียงพูดภาษาไทยในเครื่องได้แม่นแค่ไหน
เกณฑ์ผ่าน: **อัตราผิดระดับคำ (WER) ต่ำกว่า 25%** รายงานอัตราผิดระดับตัวอักษร (CER) ประกอบ

ชุดเสียงรวมราว 30 นาที
- ~25 นาทีจาก Google FLEURS ภาษาไทย ชุด test (มีบทถอดความที่ถูกต้อง, สัญญาอนุญาต CC-BY 4.0)
- ~5 นาทีเป็นเสียงพูดธรรมชาติของผู้พัฒนาเอง (อัดทีหลัง)

## ที่เก็บข้อมูล

ข้อมูลเสียงอยู่**นอก repo** ห้าม commit

```

├── .hf-cache/            ไฟล์ดิบที่โหลดจาก Hugging Face (~600 MB ลบได้ โหลดใหม่ได้)
```

## วิธีรัน

ต้องมี `uv` ทุกสคริปต์ประกาศ dependency ไว้ในหัวไฟล์ uv ติดตั้งให้เอง (Python 3.9 ของระบบเก่าเกินไป)
บน Windows ถ้าข้อความไทยในคอนโซลเพี้ยน ให้ตั้ง `PYTHONIOENCODING=utf-8`

1. โหลดชุด FLEURS (ครั้งแรกโหลด ~600 MB ไม่ต้อง login)
   ```
   uv run --python 3.12 fetch_fleurs_th.py
   ```
   เลือกหนึ่งเสียงต่อหนึ่งประโยค (ประโยคไม่ซ้ำกัน) ตามลำดับในไฟล์จนครบ 25 นาที ผลลัพธ์คงที่ทุกครั้ง
   ตัวเลือก `--out DIR` และ `--minutes N`
   ผลที่ได้ตอนนี้: 123 ประโยค รวม 25.2 นาที

2. ตรวจตัวคำนวณ
   ```
   uv run --python 3.12 wer.py --self-test
   ```

3. คำนวณคะแนน
   ```
   uv run --python 3.12 wer.py "F:/Haku Project/data/asr-th/fleurs/manifest.csv" hyps.csv --details details.csv
   ```
   `--details` เขียนคะแนนรายประโยคพร้อมคำที่ตัดได้ ไว้ดูว่าผิดตรงไหน

## วิธีคำนวณ

1. ปรับข้อความทั้งบทถอดความที่ถูกต้องและผลจากโมเดลด้วยกติกาเดียวกัน
   Unicode NFC · ลบอักขระความกว้างศูนย์ · เลขไทยเป็นเลขอารบิก · ตัวพิมพ์เล็ก ·
   เครื่องหมายวรรคตอนกลายเป็นช่องว่าง · ลบช่องว่างที่อยู่ระหว่างอักษรไทยสองตัว (ช่องว่างภาษาอังกฤษคงไว้)
2. ตัดคำด้วย PyThaiNLP `newmm` แล้วนับระยะแก้ไข (แทน/แทรก/ลบ) เป็น WER
3. CER นับจากตัวอักษรหลังปรับ โดยไม่นับช่องว่าง
4. คะแนนเป็นระดับทั้งชุด: จำนวนที่ผิดรวม ÷ จำนวนคำ (หรือตัวอักษร) ในบทถอดความที่ถูกต้องรวม

ข้อควรรู้: พจนานุกรม `newmm` มีคำประสม เช่น "กินข้าว" "ดีมาก" เป็นคำเดียว
ผิดส่วนเดียวจึงนับผิดทั้งคำ WER ไทยจึงมักสูงกว่า CER มาก ให้ดู CER ประกอบเสมอ
ถ้าไฟล์ใดไม่มีผลจากโมเดล จะนับเป็นข้อความว่าง (ลบทุกคำ) และขึ้นคำเตือน

## เพิ่มเสียงของผู้พัฒนาเอง (~5 นาที)

1. อัดเสียงพูดธรรมชาติ แยกเป็นไฟล์ละ 5–30 วินาที (Gemma รับเสียงได้ครั้งละไม่ยาวมาก)
2. แปลงเป็น **WAV 16 kHz mono 16-bit PCM** ตั้งชื่อไม่ซ้ำกับ FLEURS เช่น `own_001.wav`
   ```
   ffmpeg -i input.m4a -ar 16000 -ac 1 -c:a pcm_s16le own_001.wav
   ```
3. วางไว้ที่ `F:/Haku Project/data/asr-th/own/wav/`
4. เขียน `own/manifest.csv` (UTF-8) หนึ่งบรรทัดต่อหนึ่งไฟล์ บทถอดความพิมพ์ตามที่พูดจริงทุกคำ
   ```
   file,duration_s,reference_text
   wav/own_001.wav,12.4,วันนี้ต้องไปรับของที่ไปรษณีย์ก่อนห้าโมงเย็น
   ```
   `duration_s` ไม่ใช้ในการคำนวณ ใส่ไว้เพื่อรวมเวลา
5. รันคะแนนแยกชุด หรือรวมสองชุดโดยต่อ manifest เข้าด้วยกัน (ตัดหัวตารางซ้ำออก)

## ไฟล์ผลจากแอปในเครื่อง (hyps.csv)

แอปฝั่ง Android (งานอีกชิ้น) จะป้อนแต่ละไฟล์เสียงให้ Gemma 4 พร้อมคำสั่งให้ถอดความ แล้วเขียนผลเป็น CSV

- UTF-8 มีแถวหัวตาราง ใช้ CSV มาตรฐาน (ข้อความที่มีจุลภาคต้องครอบด้วย `"`)
- คอลัมน์บังคับ `file` ต้องตรงกับคอลัมน์ `file` ใน manifest ทุกตัวอักษร เช่น `wav/14009510506874278149.wav`
- คอลัมน์บังคับ `hypothesis_text` ข้อความที่โมเดลถอดได้ ไม่ต้องปรับอะไร ตัวคำนวณปรับให้เอง
- คอลัมน์อื่น เช่น `latency_ms` ใส่เพิ่มได้ ตัวคำนวณไม่อ่าน

```
file,hypothesis_text,latency_ms
wav/14009510506874278149.wav,มหาพีระมิดแห่งกีซาคือหนึ่งในเจ็ดสิ่งมหัศจรรย์...,2310
```
