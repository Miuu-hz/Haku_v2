> ที่มา: `01-แนวทางและหลักคิด.docx` หัวข้อ 7 · `03-กลยุทธ์ภาษาไทย.md` หัวข้อ 11

เกณฑ์ผ่านของ P0.1: อ่านแล้วอธิบายให้คนนอกเข้าใจได้ว่าทำไมไม่ใช้ Flutter ต่อ และฟอร์มลงชื่อเปิดรับได้จริง

## 1. บันทึกการตัดสินใจ

รูปแบบ: **เลือก** · ทางที่พิจารณา · ทำไมไม่เลือกทางอื่น · ทบทวนเมื่อ

### แพลตฟอร์มและโครงสร้าง

**D1 ภาษาและแพลตฟอร์ม — Kotlin Multiplatform + Compose Multiplatform**
- พิจารณา: Flutter ต่อจาก v1 · KMP · Android native ล้วน
- ไม่เลือก Flutter: ต้องทิ้งโครง Gallery และเขียนสะพานเชื่อมภาษาเอง ซึ่งคือรากปัญหาของ v1 (`chat_screen.dart` 2,773 บรรทัด ไม่มีเทสต์)
- ไม่เลือก Android native ล้วน: ปิดทาง iOS โดยต้องรื้อแกนภายหลัง
- ทบทวนเมื่อ: P0.4 ชิ้น ก ไม่ผ่าน

**D2 ลำดับแพลตฟอร์ม — Android อย่างเดียวถึงชั้น 8**
- พิจารณา: ทำสองระบบพร้อมกัน · Android ก่อน
- ไม่ทำพร้อมกัน: คนเดียวทำไม่จบ ไม่มีเครื่อง iOS และ Gallery รันบน Android เท่านั้น
- ทบทวนเมื่อ: มีเครื่อง iOS และก่อนเริ่มชั้น 9

**D3 โครงที่ยืม — ส่วน agent, tool, skill, MCP ของ Gallery**
- พิจารณา: ออกแบบระบบเอเจนต์เอง · ยืม Gallery
- ไม่ออกแบบเอง: เสียเวลาหลายเดือนกับของที่ Google ทำและพิสูจน์แล้ว
- ทบทวนเมื่อ: Gallery เปลี่ยน license หรือเลิกดูแล

**D12 การทดสอบ — มีเทสต์ตั้งแต่คอมมิตแรก แกนกลางเกิน 80%**
- ไม่เลือก "เขียนเทสต์ทีหลัง": v1 ไม่มีเทสต์เลยและแก้ทีละจุดไม่ได้
- ทบทวนเมื่อ: ไม่ทบทวน

### ความจำและการค้น

**D4 โมเดลความจำ — ห้าระดับแบบ OpenClaw แกนที่คัดแล้วแบ่งหมวดแบบความจำของ Claude**
- พิจารณา: SQLite ทึบแบบ v1 · ไฟล์ที่ผู้ใช้เปิดอ่านได้
- ไม่เลือก SQLite ทึบ: ตรวจสอบไม่ได้ ผู้ใช้ไม่เห็นว่าระบบจำอะไร ขัดหลักข้อ 4
- ทบทวนเมื่อ: ไฟล์ช้าเกินเกณฑ์ใน P1.3

**D5 ดัชนี — SQLite ฝังมากับแอป ทำดัชนีจากข้อความที่ตัดคำด้วยตัวตัดคำของระบบปฏิบัติการ มีการเทียบข้อความตรงเป็นตัวสำรอง** (ฉบับแก้ในเอกสาร 03)
- พิจารณา: FTS บนข้อความดิบ · trigram · ตัดคำก่อนทำดัชนี
- ไม่เลือกข้อความดิบ: ภาษาไทยไม่เว้นวรรค คะแนนความเกี่ยวข้องผิด
- ทบทวนเมื่อ: P0.4 ชิ้น ข ไม่ผ่าน

**D6 การฝังความหมาย — EmbeddingGemma 300M ในเครื่อง**
- ไม่เลือกเวกเตอร์แฮชของ v1: ไม่ใช่การฝังความหมายจริง
- ทบทวนเมื่อ: P0.4 ชิ้น ค ไม่ผ่าน หรือด่านวัดคุณภาพภาษาไทยใน P1.5 ไม่ผ่าน

**D18 ลำดับการค้นคืน — ตัวกรองเชิงโครงสร้าง → ค้นคำ → ค้นความหมาย → เดินตามลิงก์**
- ไม่เลือกค้นความหมายเป็นชั้นแรก: ระบบต้องใช้งานได้แม้ถอดชั้นนี้ออก
- ทบทวนเมื่อ: คำถามจริงเกินหนึ่งในสี่ตกลงมาถึงชั้นค้นความหมาย

**D19 การขยายคำค้น — ตารางคำพ้องที่เขียนเอง เริ่มราว 200 รายการ**
- ไม่เลือกให้โมเดลขยาย: ช้าและมั่ว
- ทบทวนเมื่อ: ตารางโตเกินดูแลไหว

### การคิดและการกระทำ

**D7 โมเดลหลัก — Gemma 4 E2B เป็นค่าเริ่มต้น E4B เมื่อเครื่องไหว**
- ไม่เลือก Gemma 3 1B: บริบทราว 1K โทเค็น ไม่พอ
- ทบทวนเมื่อ: มีโมเดลในรายการของ Gallery ที่ดีกว่าในขนาดเท่ากัน

**D8 ตัวจ่ายเจตนา — โมเดลเรียกฟังก์ชัน 270M**
- ไม่เลือกให้โมเดลหลักจำแนกเจตนา: หนักเกินสำหรับงานที่เกิดบ่อย
- ทบทวนเมื่อ: ความแม่นต่ำกว่าเกณฑ์ใน P4.6

**D21 ค้นข้อมูลภายนอก — skill เรียก API ทางการแบบ Gallery ไม่ขูดหน้าเว็บ**
- ไม่เลือกขูดหน้าเว็บ: เปราะและขัดจุดยืนเรื่องความเป็นส่วนตัว

**D22 AI ภายนอก — ผู้ใช้ใส่กุญแจเอง เห็นและยืนยันทุกครั้งก่อนส่ง**
- ไม่เลือกให้ Haku จ่ายค่า AI คลาวด์: ทำลายต้นทุนต่อผู้ใช้ใกล้ศูนย์ ซึ่งเป็นแกนของโมเดลธุรกิจ
- หมายเหตุ PDPA: การส่งแต่ละครั้งคือการส่งข้อมูลออกนอกประเทศ มาตรา 28

### ภาษาไทย (จากเอกสาร 03)

**D13 การทำให้เป็นรูปเดียว** — ข้อความทุกชิ้นผ่านชั้นทำให้เป็นรูปมาตรฐานก่อนเก็บ ทำดัชนี หรือเทียบ ต้นฉบับเก็บไว้เสมอ
**D14 การสร้างภาษาไทย** — แม่แบบที่คนไทยเขียนเป็นหลัก โมเดลเข้าใจและขัดเกลา ไม่แต่งประโยคเอง
**D15 คำลงท้ายและสรรพนาม** — ถามครั้งเดียวตอนเริ่มใช้ เก็บในโปรไฟล์ บังคับในขั้นตรวจผลลัพธ์
**D16 การถอดเสียงยาว** — มีเงื่อนไข: ผ่านเกณฑ์ P0.4 ชิ้น ง ถอดในมือถือ ไม่ผ่านส่งเครื่องที่บ้าน
**D17 การเก็บศักราช** — ภายในเก็บ ค.ศ. และเขตเวลามาตรฐาน แสดงผล พ.ศ. ที่ชั้นแสดงผล
**D20 หลายภาษา** — ภาษาเป็นพารามิเตอร์ตั้งแต่แรก ภาษาไทยเป็นภาษาแรก ยังไม่ทำภาษาที่สองจนมีผู้ใช้ขอ

### อุปกรณ์ ความปลอดภัย ดีไซน์

**D9 เสียง — ใช้ความสามารถรับเสียงของโมเดลหลักที่โหลดอยู่แล้ว**
- ไม่เลือกโหลดโมเดลถอดเสียงแยก: กินหน่วยความจำเพิ่ม
- ทบทวนเมื่อ: P0.4 ชิ้น ง ไม่ผ่าน

**D10 เครื่องที่บ้าน — มือถือเก่าหรือ PC ที่มีอยู่ จำกัดวงเครือข่ายบ้าน**
- ทบทวนเมื่อ: เริ่ม P7.1 ประเมิน google/artemis · Hermes · OpenClaw

**D11 การเข้ารหัส — เข้ารหัสฐานข้อมูลและไฟล์ ล็อกด้วยชีวมิติผ่าน API ของระบบ**
- หมายเหตุ PDPA: แอปได้แค่ผ่าน/ไม่ผ่าน ไม่ได้ประมวลผลข้อมูลชีวมิติเอง

**D23 ทิศทางดีไซน์ — ธีมสว่างแนว One UI สีพาสเทล ไอคอน 3D**
- ไม่เลือกธีมมืด Haku Crystal: ออกมาเป็น cyberpunk ไม่ตรงความรู้สึกที่ต้องการ

## 2. ขอบเขตรุ่นแรก (รุ่นทดสอบปิด จบช่วงที่ 3)

**มี**
- ไดอารีอัตโนมัติจากตำแหน่งและนัดในปฏิทิน · สรุปเย็นภาษาคน
- ความจำที่เก็บ ค้นคำ และบอกที่มาได้ · หน้าความโปร่งใสและการลืม
- หน้าแรก ไทม์ไลน์ การเริ่มใช้งานครั้งแรก
- Android เท่านั้น ภาษาไทยเท่านั้น

**ไม่มี** (ระบุชัดเพื่อไม่ให้งานบาน)
- iOS · ภาษาที่สอง
- แชทเต็มรูป (P3.3) · วิดเจ็ต (P3.5) · ค้นความหมาย (P1.5) · ย่อยตอนกลางคืน (P1.8)
- เสียง · ทักษะและเครื่องมือภายนอก · การทักก่อน
- เครื่องที่บ้าน · ผู้ช่วยคุยกันเอง · ระบบชำระเงิน
- เซิร์ฟเวอร์เก็บข้อมูลผู้ใช้ทุกชนิด

## 3. เกณฑ์การเลิกทำหรือเปลี่ยนแผน

| เมื่อ | ถ้า | ทำอะไร |
|---|---|---|
| จบ P0.4 ชิ้น ก | Gallery รันโมเดลผ่านชั้นห่อหุ้มบนเครื่องจริงไม่ได้ | หยุด ทบทวน D1 D3 ก่อนเขียนโค้ดต่อ |
| จบ P0.4 ชิ้น ข | ค้นคำไทยกลางประโยคไม่เจอ หรือหมื่นรายการเกิน 50 ms | หยุด ทบทวน D5 |
| จบ P0.4 ชิ้น ง | อัตราผิดระดับคำเกิน 25% | ย้ายชั้นเสียงไปท้ายช่วงที่ 6 นำร่ององค์กรด้วยไดอารี |
| ระหว่างช่วงที่ 2–3 | แอปใช้แบตเกิน 8% ต่อวัน | หยุดเพิ่มฟีเจอร์ แก้พลังงานก่อน |
| ขอสิทธิ์ตำแหน่งเบื้องหลัง | Google Play ปฏิเสธ | โหมด geofence และการแจ้งเมื่อกิจกรรมเปลี่ยนอย่างเดียว |
| จบช่วงที่ 3 | การกลับมาใช้วันที่ 7 ต่ำกว่า 40% | แก้ผลิตภัณฑ์ก่อน ไม่เปิดขาย |
| จบช่วงที่ 4 | อัตราแปลงเป็นผู้จ่ายต่ำกว่า 1% | ย้ายน้ำหนักไปตลาดองค์กร |
| ทุกช่วง | เฟสใดเกินสามสัปดาห์โดยไม่มีของรัน | ซอยเฟส หรือหยุดที่จุดหยุดล่าสุด |
