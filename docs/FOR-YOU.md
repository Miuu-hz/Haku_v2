## 1. ทดสอบชิ้น ก บน Z Fold5 (~20 นาที) — สำคัญที่สุด
เป็นเกณฑ์ผ่านที่ขวางทั้งแผน (ถ้าไม่ผ่านต้องทบทวน D1 D3) โมเดล Gemma 4 E2B ดาวน์โหลดไว้แล้วที่ `F:\Haku Project\models\gemma-4-E2B-it.litertlm` (2.4 GB)

เตรียมเครื่อง: เปิด Developer options → USB debugging แล้วเสียบสาย จากนั้นใน Git Bash:
```bash
export JAVA_HOME="/f/Android Studio/jbr"; export PATH="$PATH:/f/AndroidSDK/platform-tools"
cd "/f/Haku Project/haku-v2"
adb devices        # ถ้ามี emulator ด้วย ให้ใส่ -s <serial ของ Fold5> ทุกคำสั่ง adb
adb shell mkdir -p /data/local/tmp/haku
adb push "F:/Haku Project/models/gemma-4-E2B-it.litertlm" /data/local/tmp/haku/
./gradlew --no-daemon :androidApp:installDebug

# GPU (รัน 2-3 รอบ รอบแรกมีการอุ่นเครื่อง)
adb logcat -c
MSYS_NO_PATHCONV=1 adb shell am start -S -n com.bbpillow.haku/.SpikeActivity --es model /data/local/tmp/haku/gemma-4-E2B-it.litertlm --es backend gpu
adb logcat -s HakuSpike:I          # รอจนขึ้น DONE หรือ ERROR แล้วกด Ctrl+C

# CPU
adb shell am force-stop com.bbpillow.haku; adb logcat -c
MSYS_NO_PATHCONV=1 adb shell am start -S -n com.bbpillow.haku/.SpikeActivity --es model /data/local/tmp/haku/gemma-4-E2B-it.litertlm --es backend cpu
adb logcat -s HakuSpike:I
```
อ่านค่า: `LOAD ms` เวลาโหลด · `ttftMs` เวลาโทเค็นแรก · `tokPerSec` ความเร็ว · `pssMB` หน่วยความจำ
**ส่งผลลัพธ์ใน logcat ให้ Claude** แล้วจะบันทึกลง `docs/spikes/` ให้ ผ่านเมื่อ: มีคำตอบภาษาไทยขึ้นบนเครื่อง และวัด TTFT ได้

หมายเหตุ: บน emulator ทดสอบได้แค่ว่า native library โหลดได้ (ผ่านแล้ว) เพราะ emulator มี RAM 2 GB ไม่พอสำหรับโมเดล

## 16. ติดตั้งจริงครั้งแรก (แอปเต็ม)
แอปเปิดขึ้นที่หน้าเริ่มใช้งานจริงแล้ว (ไม่ใช่ข้อมูลจำลอง) ทดสอบบน Z Fold5 ราว 20 นาที + เวลาดาวน์โหลดโมเดล (~2.6 GB ใช้ Wi-Fi)
1. ติดตั้งแบบเริ่มใหม่: `adb uninstall com.bbpillow.haku` แล้ว `./gradlew --no-daemon :androidApp:installDebug`
2. เปิด log ไว้อีกหน้าต่าง: `adb logcat -s HakuShell HakuModel HakuCapture AndroidRuntime`
3. เปิดแอป → หน้าเริ่มใช้งาน ทำตามทีละขั้น:
   - **สิทธิ์**: ทุกข้อเริ่มจาก "ปิด" ติ๊กตำแหน่ง กิจกรรม ปฏิทิน แล้วกดขอ → ระบบถามตำแหน่ง (เลือก "ขณะใช้แอป") กิจกรรม ปฏิทิน ทีละหน้าต่าง
     ถ้าติ๊กตำแหน่งเบื้องหลังไว้ด้วย ระบบจะถามแยกหลังสุด (Android 11+ มักพาไปหน้าตั้งค่า ให้เลือก "อนุญาตตลอดเวลา" แล้วกดย้อนกลับ)
   - **คำลงท้าย/ชื่อเรียก**: ดูตัวอย่างไดอารีเปลี่ยนตาม
   - **โมเดล**: เครื่อง 12 GB ควรเห็นทั้ง E2B และ E4B กดดาวน์โหลด ดูแถบคืบหน้าวิ่ง ลองกดหยุด → เล่นต่อ (ควรต่อจากเดิม ไม่เริ่ม 0)
     ลองพับ/กางเครื่องระหว่างดาวน์โหลด ไม่ควรเริ่มใหม่ · ไฟล์ไปอยู่ที่ `/sdcard/Android/data/com.bbpillow.haku/files/models/` (`.part` ระหว่างโหลด)
   - **ล็อก**: กดเปิด → หน้าต่างสแกนนิ้ว/PIN ของระบบ
   - **สถานที่แรก**: ติดตั้งใหม่มักยังไม่มีข้อมูล ข้ามได้
   - กด "เริ่มใช้ Haku" → เข้าแท็บหน้าแรก / ไทม์ไลน์ / ความจำ
4. ตรวจว่าการจับข้อมูลเริ่มแล้ว (เริ่มเฉพาะเมื่อให้ตำแหน่ง + กิจกรรม): `adb logcat -s HakuCapture` ควรเห็นบรรทัดเริ่ม
   หรือ `adb shell am broadcast -n com.bbpillow.haku/.CaptureDebugReceiver -a com.bbpillow.haku.debug.DUMP`
5. ปิดแอปจาก recent แล้วเปิดใหม่ → ถ้าเปิดล็อกไว้ต้องสแกนก่อน · ไม่ควรกลับไปหน้าเริ่มใช้งาน
6. ถ้าดาวน์โหลดค้างตอนปิดแอป: เปิดแอปใหม่ ระบบต่อจากไฟล์ `.part` เอง
7. ลองโหลดโมเดลที่ดาวน์โหลดมา: `adb shell am start -n com.bbpillow.haku/.SpikeActivity` (ไม่ใส่ `--es model` จะใช้ไฟล์ที่ดาวน์โหลดในแอป) ดู `adb logcat -s HakuSpike`
8. ตั้งแบตเป็น "Unrestricted" แล้วใช้ชีวิตหนึ่งวัน พรุ่งนี้เปิดแท็บหน้าแรก กดการ์ดเมื่อวาน → ควรเปิดวันนั้นในไทม์ไลน์

ส่ง Claude: บรรทัด error ใน logcat (ถ้ามี) · หน้าจอที่ค้างหรือว่าง · เวลาที่ใช้ดาวน์โหลด
ข้อจำกัดที่รู้: ดาวน์โหลดไม่มี foreground service ถ้าปิดจอนานระบบอาจหยุด (เปิดแอปใหม่ต่อได้) · ไม่ตรวจ hash ไฟล์ ตรวจแค่ขนาด · ฐานข้อมูลยังไม่เข้ารหัส ล็อกเป็นแค่ประตู (D11)

เดือนนี้ มีข้อมูล 30 จาก 30 วัน

## 18. หลังแก้บั๊ก Android — จุดที่ต้องดูบน Fold5
- เสี่ยงสุด: สรุปเย็นกับเอเจนต์ใช้ engine โมเดลตัวเดียวกันแล้ว (ประหยัด RAM) ยังไม่รู้ว่า LiteRT-LM 0.11 ยอมให้สองบทสนทนาพร้อมกันไหม — ลองเปิด AgentSpikeActivity แล้วตามด้วย SummarySpikeActivity ขณะตัวแรกยังทำงาน ถ้าพังบอก Claude จะใส่ล็อกให้ทีละบทสนทนา
- รอพิกัดสูงสุด 8 วินาทีต่อการปลุก — ดู logcat ว่าไม่มีคำเตือน broadcast timeout
- ปิดสิทธิ์ตำแหน่งเบื้องหลัง → ระบบไม่ตั้ง geofence ใช้แค่การเปลี่ยนกิจกรรม ดูว่าการออกจากที่ยังถูกจับได้
- รีบูตเครื่อง / อัปเดตแอป → การจับข้อมูลกลับมาทำงานเอง

## 19. งานกลางคืน P2.7 (NightlyWorker · ทดสอบบน Fold5)
- ตั้งเองครั้งแรกที่เข้าหน้าหลักหลัง onboarding: ทุก 3 ชม. เมื่อ **ชาร์จ + เครื่องว่าง (จอดับสักพัก) + แบตไม่ต่ำ** ทำไดอารีเมื่อวาน/วันนี้ แล้วสรุปเย็นด้วยโมเดลถ้าไฟล์โมเดลโหลดครบ (วันนี้สรุปหลัง 21:00 เท่านั้น เพราะสรุปเก็บครั้งเดียวต่อวัน)
- สั่งรันทันทีแบบไม่สนเงื่อนไข (debug): `adb shell am broadcast -n com.bbpillow.haku/.CaptureDebugReceiver -a com.bbpillow.haku.debug.NIGHTLY` แล้ว `adb logcat -s HakuNightly`
- สั่งงานจริงตัวที่ตั้งไว้ (ทดสอบเงื่อนไข): `adb shell dumpsys jobscheduler | grep -B2 -A10 com.bbpillow.haku` หา `#u0a…/<JOB_ID>` ของ SystemJobService แล้ว `adb shell cmd jobscheduler run -f com.bbpillow.haku <JOB_ID>` (`-f` = ข้ามเงื่อนไข) · จำลองเครื่องว่าง: `adb shell cmd deviceidle force-idle` / คืน `adb shell cmd deviceidle unforce`
- ที่ต้องเห็น: `diary composed for [เมื่อวาน, วันนี้]; model=true summarize=[...]` ตามด้วย `summary <วัน> source=MODEL` และ metrics (< 30 วินาที/วัน) · รันซ้ำคืนเดียวกันต้องได้ `summarize=[]` (ไม่โหลดโมเดล) · หลังงานจบ RAM ของแอปต้องลดลง (Android Studio profiler หรือ `adb shell dumpsys meminfo com.bbpillow.haku`) = engine ถูกปล่อยแล้ว
- หน้าแรก: การ์ดเรื่องของวันแสดงข้อความสรุปแทนสามบรรทัดแรก และมีการ์ด "สรุปสัปดาห์นี้" (แผนฟรี: ไม่เทียบสัปดาห์ก่อน มีชิป Haku Plus)
- ถ้าเห็น `source=TEMPLATE rejected=[...]` ทุกคืนสำหรับวันเดิม = โมเดลไม่ผ่านตัวตรวจซ้ำ ๆ งานจะลองใหม่ทุกรอบที่ชาร์จ บอก Claude ให้ใส่บันทึกจำนวนครั้ง

## 21. Dream — การย่อยความจำตอนกลางคืน (ตัดสินใจค่าเกณฑ์)

รายงานการย่อยความจำ คืนวันที่ 2026-09-30

## 20. ลืม/ส่งออก P3.4 (ทดสอบบน Fold5)
- ไทม์ไลน์: ลบหรือแก้บรรทัดของวันที่มีสรุปเย็นแล้ว → สรุปของวันนั้นหายทันที คืนนั้น NightlyWorker เขียนใหม่ (ไม่มีบรรทัดที่ลบ) · วันอื่นไม่ถูกแตะ
- แท็บความจำ: ปุ่ม "ลืมทั้งหมวดนี้" ใต้แต่ละหมวด (มีข้อความถึงจะโชว์) → ยืนยัน → หมวดว่าง และค้นหาไม่เจอข้อความเดิม
- ปุ่ม "ส่งออกความจำทั้งหมดเป็นไฟล์" เปิดตัวเลือกบันทึกไฟล์ของ Android (SAF) → ได้ `haku-memory.md` ที่เปิดอ่านได้ (คำสั่งถาวร · หมวด · บันทึกรายวัน · รายงานความฝัน) · ผู้ใช้เลือกที่เก็บเอง ไม่ใช่การส่งข้อมูลออกนอกเครื่อง ตัวนับ egress ยังเป็น 0
- ปุ่ม "ลืมทุกอย่าง": ต้องพิมพ์ "ลืมทุกอย่าง" ก่อนปุ่มยืนยันทำงาน → ลบไฟล์ความจำ ดัชนี เหตุการณ์ที่จับ สถานที่ บัญชีไดอารี และสรุปเย็น · การตั้งค่าตอนเริ่มใช้ (สไตล์ โมเดล ล็อก) อยู่ต่อ
- ดู: หลังลืมทุกอย่าง รัน NightlyWorker (debug receiver) แล้วหน้าไทม์ไลน์ต้องว่าง ไม่มีบรรทัดเก่ากลับมา · เหตุการณ์ที่จับใหม่หลังจากนั้นเริ่มสะสมตามปกติ
- คำถามตัดสินใจ: "ลืมทุกอย่าง" เก็บสไตล์/ชื่อเล่นไว้ (เป็นค่าตั้งค่า) ต้องการให้ล้างชื่อเล่นด้วยไหม · id ของเหตุการณ์ที่ถูกลืมยังอยู่ในตาราง deleted_ids (เก็บแค่ id ไม่มีเนื้อหา เพื่อกันปฏิทินดึงกลับ)

## 22. Dream ต่อเข้างานกลางคืน + รายงานในหน้าความจำ
- Dream รันต่อท้าย NightlyWorker (หลังไดอารีและสรุปเย็น ไม่ต้องมีโมเดล) สำหรับ "เมื่อวาน" ตามวันท้องถิ่น ใช้ชื่อวันนั้นเป็นวันของ Dream ตรง ๆ (D17: ไฟล์ daily เป็นวัน UTC; อ่านย้อนถึงไฟล์ UTC ของวันนั้น ครอบคลุมเมื่อวานท้องถิ่นทั้งวันสำหรับโซนตะวันออกของ UTC เช่นไทย) · รันได้คืนละหนึ่งรายงาน รอบที่สองของคืนเดียวกันไม่ทำอะไร
- บังคับรันบนเครื่อง (ต้องผ่านการเริ่มใช้งานแล้ว): `adb shell am broadcast -n com.bbpillow.haku/.CaptureDebugReceiver -a com.bbpillow.haku.debug.NIGHTLY` แล้ว `adb logcat -s HakuNightly` ต้องเห็น `dream <เมื่อวาน> alreadyRan=false tidied=… promoted=… held=…` · สั่งซ้ำ = `alreadyRan=true`
- อยากรันใหม่ในคืนเดิม: ต้องลบรายงานของคืนนั้นก่อน (ตอนนี้ยังไม่มีปุ่ม) หรือกด "ลืมทุกอย่าง" · เลื่อนขั้นเป็นความจำถาวรได้จริงต้องมีข้อมูลซ้ำอย่างน้อย 3 วัน
- ดูรายงาน: แท็บความจำ (Transparency) เลื่อนลงเห็นหัวข้อ "รายงานการย่อยความจำ" 7 คืนล่าสุด คืนล่าสุดอยู่บนสุด · ไฟล์ทะเบียนของ Dream (วัน `0000-00-00`) ไม่แสดงและไม่อยู่ในไฟล์ส่งออก แต่ "ลืมทุกอย่าง" ลบให้
- แก้บั๊ก: ขั้นจัดของไม่ลบบรรทัดไดอารีอีกแล้ว (ลบเฉพาะข้อความที่ผู้ใช้พิมพ์ซ้ำทุกตัวอักษร สำเนาจากภายนอก และสิ่งที่ตั้งใจจะทำ) · "ลืมทุกอย่าง" ล้างชื่อเล่นด้วย (PDPA) คงสไตล์คำลงท้าย/โมเดล/ล็อก
- คำถามตัดสินใจ: ยังไม่มีโมเดลช่วยเรียบเรียงข้อเท็จจริง (ใช้แม่แบบ) · ต้องการปุ่ม "ย่อยใหม่" ในหน้าความจำไหม
